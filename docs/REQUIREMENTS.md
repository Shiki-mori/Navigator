# Navigator 需求说明（MVP）

个人本地打卡应用。无账号、无网络、无云同步。

## 用户故事

1. 作为使用者，打开应用后能看到**当前连续日**和**历史最长连续日**。
2. 作为使用者，我能为**今天**记录：自慰次数、房事次数、是否看黄、是否遗精、坏习惯（无 / 熬夜 / 通宵），并保存。
3. 作为使用者，我能在**月历**中查看每天状态，并补打或修改不晚于今天的日期。
4. 作为使用者，我能查看**月视图 / 年视图**折线图（可多选破戒、自慰、看黄等条目）以及汇总数字；也可看全部时段汇总。
5. 作为使用者，我能**导入**旧软件或本应用导出的 JSON，记录条数与源文件一致。
6. 作为使用者，我能**导出** JSON，再导入后数据一致。
7. 作为使用者，**进入应用且当日尚未打卡**时，系统自动为当日及往前 5 天内的空缺日补上干净打卡，并提示补打了哪些日期。

## 领域规则

### 破戒

当日满足任一条件即为破戒：

- 自慰次数 ≥ 1
- 看黄为真

房事、遗精、熬夜、通宵**不断**连续日。

### 破戒次数

按日计算后再在月/年视图中求和：

- 当日**有自慰**（无论是否同时看黄）：破戒次数 = 自慰次数。
- 当日**仅看黄、未自慰**：破戒次数 = 1。
- 当日既无自慰也无看黄：破戒次数 = 0。

连续日是否中断仍只看是否破戒（有无自慰或看黄），不看次数多少。

### 连续日

- **干净日**：该日已有记录，且未破戒。
- **未记录日**不视为成功日，会打断连续。
- `trackingStartDate`（旧数据中的 `first_start`）**之前**的缺日视为未记录，不得把空洞日期算进连续成功。
- 今天尚未打卡：当前连续日统计到**昨天**为止的干净日。
- 今天已打卡且未破戒：当前连续日**含今天**。
- 今天已打卡且已破戒：当前连续日 = 0。

### 自动打卡

- **始终开启**，设置页无开关。
- **触发**：进入应用界面（冷启动，或从后台回到前台）。仅切换底部 Tab 不重复触发。
- **前置条件**：当日尚无记录。当日已有记录则整次跳过，即使窗口内更早的日期仍空缺也不补。
- **窗口**：`[今天 − 5 天, 今天]`，共 6 个自然日。
- **写入**：只补**未记录**日，不覆盖已有记录。内容为干净默认（自慰/房事 0、不看黄、不遗精、无坏习惯）。
- **追踪日**：已有开始追踪日时，不早于该日补打。尚无追踪日时，第一次写入会把该日设为开始追踪日。
- **提示**：若实际写入了至少一天，Snackbar 列出日期，例如 `已自动打卡：2026-09-07、2026-09-12`。
- 不允许为未来日期打卡（窗口不含未来）。

### 数据

- 忽略旧备份中的 `yy`、`yw`。
- 导入时若同一天出现多条，后写覆盖先写。
- 导入采用**全量替换**（记录与开始追踪日一并替换）。
- 不允许为**未来日期**打卡。

## 验收标准

| 编号 | 标准 |
|------|------|
| A1 | 首页展示当前连续日、最长连续日；未打卡时表单可编辑并保存。 |
| A2 | 保存后杀进程再打开，当天记录仍在。 |
| A3 | 月历：干净日、破戒日、未记录日可区分；点击某日可编辑。 |
| A4 | 导入清洗后的 JSON，条数与源 `records` 一致，`first_start` 映射为开始追踪日。 |
| A5 | 导入仍含 `yy`/`yw` 的原始备份时忽略这两字段且成功。 |
| A6 | 导出后再导入，记录内容与开始追踪日一致。 |
| A7 | 单元测试覆盖：解析映射、连续日边界、开始日之前缺日、统计汇总、破戒次数规则。 |
| A8 | 月/年视图「破戒次数」：有自慰记自慰次数；仅看黄记 1。 |
| A9 | 进入应用且当日未打卡时，为今日及往前 5 天空缺日写入干净记录并 Snackbar 提示；当日已打卡则不补历史空缺。 |
